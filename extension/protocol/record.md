# 记忆库协议 — 记录（Record）

由 `/memory record` 触发。向库根写任何内容前，先读本手册与 entities.md（库根定义见 entities.md）。

## 原则

记忆库是被动的：只在明确请求时写入。

**价值判定归发起记录的人**——`/memory record` 这个动作本身就是一次"这条值得留下"的判断。
所以写时不要求你猜"以后会不会用到"（写时确实猜不准），只要求一条硬门槛：

**写进正文的每个断言都必须可核对**——存在某种观察能推翻它（命令输出、源码、页面原文、用户原话）。

- 可核对 → 写入；验证留到有人用它的时候（见 verify.md），不必当场验。
- 不可核对（纯偏好、氛围、"助手应当如何"的自我承诺）→ 不进正文；确有留存必要写进 `sources`。
- 单会话内就会失效的过程细节 → 不入库。

## 写入

- 新建：写 `entities/<id>.md`（id/kind 校验见 entities.md）。
- 更新：用新断言重写正文——新断言续接编号，替换断言保留原编号；新出处追加进 `sources`。
- 修正（验证失败后的纠错）：按该实体最新 failed 记录首行的无效断言编号定位，只改被推翻的断言，
  保留其余断言与编号。修正后实体自动降为 stale——这是预期状态，修完必须跟一次验证（见 verify.md）。
- 更新正文不删任何验证记录（stale 由时间戳规则自动得出）；改 id 等于新建实体，不要重命名文件。

## 边界

`verifications/` 只由验证流程追加，记录流程绝不写、改、删其中任何内容。
