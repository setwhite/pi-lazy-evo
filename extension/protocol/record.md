# 记忆库协议 — 记录（Record）

由 `/memory record` 触发。向 `.memory/` 写任何内容前，请先读本手册与 entities.md。

## 原则

- 记忆库是被动的：除非明确请求，否则不记录任何内容。
- 只有值得日后引用的长期结论才入库；临时性细节永不入库。

## 写入（新建 / 更新 / 修正）

- 新建：为实体写 `entities/<id>.md`；先校验 id 与 kind（见 entities.md）。
- 更新：用新断言重写正文，**断言以 `A1:` 起逐条编号**；新断言续接编号，替换断言保留原编号；
  把新出处追加进 `sources`（以 `；` 分隔，绝不重复已有出处）。
- 修正（验证失败后的纠错）：只改被推翻的断言（按验证记录正文的无效断言编号定位），
  保留其余断言与编号；**修正后实体自动成为 stale（需复验）**——这是预期状态，不是事故。
  修正走完必须跟一次验证（见 verify.md），验证通过才算收敛。
- 描述本仓库代码/配置行为的实体，front-matter 填 `depends-on`（仓库内相对路径，逗号分隔，
  如 `extension/auto.ts`；只列直接影响断言的文件，不列间接依赖）。
- 更新正文不删任何验证记录——stale 由时间戳规则自动得出。
- 改 id 等于新建实体；不要重命名文件。

## 与验证记录的边界

验证记录只由验证流程追加（verify.md）。记录流程绝不写、改、删 `.memory/verifications/` 下的任何内容。

## Git

`.memory/` 是个人运行时数据，不随仓库分发（gitignore）。绝不提交记忆库变更。
