# 记忆库协议 — 验证记录

验证记录位于 `<库根>/verifications/`，追加前请把本手册与操作手册一起读完。实体格式见 entities.md。

## 格式

路径 `verifications/<实体id>/<日期>[-N].md`：目录名即实体 id，只追加、绝不修改旧文件。
只看自己实体的目录，不要碰其他实体、不要全局重排文件名。日期只防重名，门控不读文件名。

**防重名由你负责**（扩展不写库，不会替你命名）：追加前先列出该实体目录，
`<日期>.md` 已存在则用 `-2.md`，再存在则 `-3.md`……**直接写已存在的文件名就是覆盖旧记录**，
历史不可审计，是本协议最严重的违规。

| 字段 | 取值 |
|---|---|
| target | `entities/<id>.md` |
| validator | 见下方验证器 |
| checked_at | 当前真实时间的 ISO 时间戳（见时间戳纪律） |
| result | passed / failed |

front-matter 恰好这四个字段。正文（front-matter 之外的全部内容）是证据——自由文本，承载可复核依据
（来源、命令输出、用户原话）。**证据必填：没有正文的记录不算验证。**

**failed 记录正文第一行必须是无效断言编号清单**（如 `无效断言：A2, A5`），随后写推翻依据；
passed 记录如发现措辞瑕疵也照此标注。编号让修正动作有精确落点。

不合规的记录（target 不是 `entities/<id>.md`、result 非法、checked_at 非 ISO）会被扩展忽略。

## 时间戳纪律（硬约束）

`checked_at` 是门控 stale 判定的唯一时间依据，必须写执行验证那一刻的**真实当前时间**：
追加记录前先运行 `date` 取系统时间，原样填入（保留时区）。禁止推断、回溯、占位或编造——
错误时间戳会把实体永久钉在 stale，或让过期验证冒充新鲜，两种情况都污染门控。

## 验证器：按证据独立性分级

`validator` 记的是**证据与被验对象的独立程度**，不是用了什么工具。判据只有一条：
**如果被验对象是假的，这个机制会不会报错。**

下表行序即等级由低到高。**没有工具权重**——手段（grep / rg / web / git / 问用户）写进正文证据，
不参与定级。一条记录只写一个 validator，取本次实际达到的最高等级。

| validator | 判据 | 能证明 | 不能证明 |
|---|---|---|---|
| `claim` | 假时不报错 | 有人/某个模型说过这话 | 事情本身为真 |
| `quote` | 假时不报错 | 引用抄对了、来源确实存在 | 来源自己没说错 |
| `corroborate` | 偶尔报错 | 去掉共同上游后仍有 ≥2 个独立来源 | 共享上游的多源不算（先查来源血缘再计数） |
| `recompute` | 会报错 | 你亲手复算出的结果：命令输出、页面原文、代码编译 | 与被验对象有共同设计者时只算 `quote` |
| `falsify` | 会报错，且我试过 | 先写下证伪条件、主动找过反例、没找到 | 没找过反例就不许记这一级（配 `passed` 意为"没推翻"） |

### 定级纪律

- **共享上游的自验不算验证**：核对自己刚写下的内容（同一会话、同一模型、同一份转录）至多记 `quote`。
  不得因为"我认真看了一遍"就记 `recompute`。
- **证据只覆盖它能证的那个断言**：命令证明了"代码里有这个调用"，不证明"这个设计是对的"。
  实体多条断言时，等级只对证到的部分成立；没证到的另开一次验证。
- **`falsify` 必须在正文写明**证伪条件是什么、去哪儿找了反例。
- **旧读法约定**：取值不在上表内（早期记录的 `format` / `conflict` / `code:` / `web-research` /
  `user-confirm`）一律按最低级 `claim` 理解——当作"有人说过"，需要时重验一次并追加新记录。
  旧记录不改动、不回填、不映射。

## 门控：四态

取实体最新的验证记录（`checked_at` 最大者），与其正文文件 mtime 对比：

| 条件 | 状态 | 处置 |
|---|---|---|
| 最新记录 passed 且晚于正文最后修改，depends-on 未变 | ✅ passed | 当事实用 |
| 最新记录 failed 且晚于正文最后修改 | ⚠️ failed | 不得当事实用；先修正正文再复验（见 verify.md） |
| 完全没有记录 | ❓ unverified | 慎用；关键决策依赖前先验证 |
| 最新记录早于正文最后修改，或 depends-on 文件在该次验证后改过 | ⏳ stale（需复验） | 旧验证不再匹配；复验或忽略 |

更新实体正文无需删除记录——时间戳规则自动把它降为 stale。依赖变化由扩展自动判定。
