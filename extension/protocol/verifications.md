# 记忆库协议 — 验证记录

验证记录位于 `<库根>/verifications/`，追加前请把本手册与操作手册一起读完。实体格式见 entities.md。

## 格式

路径 `verifications/<实体id>/<日期>[-N].md`：目录名即实体 id，只追加、绝不修改旧文件；
同日多条自动加序号（`-2.md`、`-3.md`…），只看自己实体的目录，不要碰其他实体、不要全局重排文件名。
日期只防重名，门控不读文件名。

| 字段 | 取值 |
|---|---|
| target | `entities/<id>.md` |
| validator | 见下方验证器 |
| checked_at | 当前真实时间的 ISO 时间戳（见时间戳纪律） |
| result | passed / failed |

front-matter 恰好这四个字段。正文（front-matter 之外的全部内容）是证据——自由文本，承载可复核依据
（来源、命令输出、用户原话）。**证据必填：没有正文的记录不算验证。**

**failed 记录正文第一行必须是无效断言编号清单**（如 `无效断言：A2, A5`），随后写推翻依据；
passed 记录如发现措辞瑕疵也照此标注。编号让修正动作有精确落点。

不合规的记录（target 不是 `entities/<id>.md`、result 非法、checked_at 非 ISO）会被扩展忽略。

## 时间戳纪律（硬约束）

`checked_at` 是门控 stale 判定的唯一时间依据，必须写执行验证那一刻的**真实当前时间**：
追加记录前先运行 `date` 取系统时间，原样填入（保留时区）。禁止推断、回溯、占位或编造——
错误时间戳会把实体永久钉在 stale，或让过期验证冒充新鲜，两种情况都污染门控。

## 验证器

`validator` 取值即判断权威：

| validator | 权威 | 证据要求 |
|---|---|---|
| `format` | 代理 | front-matter 与文件名结构核对 |
| `conflict` | 代理 | 通读记忆库判断重叠/矛盾，把分析写进正文 |
| `code: <命令>` | 代理 | 自己编写并运行命令（如 bash），把命令与输出写进正文 |
| `web-research` | 代理 | 联网调研，把发现写进正文 |
| `user-confirm` | 用户 | 询问用户，把确认原话写进正文 |

每条记录只写一个 validator；同时用了多种手段时写最重的一种（web > code > 读源码）。

## 门控：四态

取实体最新的验证记录（`checked_at` 最大者），与其正文文件 mtime 对比：

| 条件 | 状态 | 处置 |
|---|---|---|
| 最新记录 passed 且晚于正文最后修改，depends-on 未变 | ✅ passed | 当事实用 |
| 最新记录 failed 且晚于正文最后修改 | ⚠️ failed | 不得当事实用；先修正正文再复验（见 verify.md） |
| 完全没有记录 | ❓ unverified | 慎用；关键决策依赖前先验证 |
| 最新记录早于正文最后修改，或 depends-on 文件在该次验证后改过 | ⏳ stale（需复验） | 旧验证不再匹配；复验或忽略 |

更新实体正文无需删除记录——时间戳规则自动把它降为 stale。依赖变化由扩展自动判定。
