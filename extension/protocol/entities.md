# 记忆库协议 — 实体

实体文件位于 `.memory/entities/`，每个 `<id>.md` 一张实体。操作 `.memory/entities/` 前请先读本手册。

## 库结构（通用）

```
.memory/
├── entities/          # 实体：每个 <id>.md 一张
└── verifications/     # 验证记录：verifications/<id>/<日期>[-N].md（按实体归位，只追加）
```

目录骨架由扩展预建。直接读写文件即可，不要创建目录（追加验证记录前先确认目标实体目录存在，不存在则创建）。

## 实体文件格式

文件名即 id：任意非空单行文本（不含换行/制表符与路径分隔符），既是文件名也是唯一标识。front-matter 恰好三个必填字段，另有一个可选字段：

| 字段 | 取值 | 说明 |
|---|---|---|
| id | 与文件名一致 | 唯一标识 |
| kind | tool / person / project / concept / decision | 类型 |
| sources | URL / 本地路径 / 会话引用 | 出处 |
| depends-on | 仓库内相对路径，逗号分隔（可选） | 实体描述的代码/配置行为所依赖的文件；最新一次验证通过之后这些文件被改过 → 实体自动失效（stale，由扩展实时推导，无任何缓存文件） |

格式不合规的文件（front-matter 缺失或损坏、缺 id/kind）会被扩展忽略。

## 正文规则

- 每句一个独立可验证断言，以编号开头：`A1: <断言>`、`A2: <断言>`…，编号随更新递增、绝不复用。
- 断言用具体词（grep 可命中），不用代词；不写模糊措辞（"可能"、"我认为"）；不确定内容写进 `sources`，绝不进正文。
- 断言自洽：禁止跨实体比较或引用；一条事实不得依赖另一实体的正文。
- 正文不承载信任状态；信任由最新验证记录推导（门控规则见 verifications.md）。
- 描述本仓库代码/配置行为的实体，应填 `depends-on`（如 `depends-on: extension/auto.ts, extension/config.ts`）——代码一变实体自动失效，无需人工发现。
